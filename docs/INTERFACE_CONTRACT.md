# SenFate 2.0 公共接口契约

## 设计原则

四派只共享经过认证的排盘事实，不共享旺衰、格局、用神或主题结论。每次请求都产生一个可保存、可复查的计算证书。

```text
出生时空输入
  → 地点 / IANA 时区
  → 民用时刻解析
  → 真太阳时与节气窗口
  → 四柱与起运
  → ChartIR
  → 四派独立原局 / 大运 / 流年推演
```

## 排盘接口

`POST /api/chart/compile`

输入：出生年月日时分、地点 ID 或精确经纬度、IANA 时区、性别、时刻歧义选择。

输出：

- 地点与坐标来源；
- 时区候选和最终选择；
- 真太阳时修正（经度修正、均时差、总修正）；
- 前后节气与不确定性窗口；
- 年月日时四柱、藏干、十神；
- 起运方向、起运年龄区间和八步大运；
- `ChartIR` 与完整上游计算证书。

任何跨越节气、换日或时辰边界的不确定输入均返回明确的关闭状态，不生成猜测性四柱。

## 分析接口

`POST /api/analysis/run`

输入：`ChartIR`、目标阶段（原局 / 大运 / 流年 / 流月）、目标年份或大运、流派 ID（单派或全部）。

输出：各派分别的结论、主题、规则触发记录、规则追踪、来源锚点和年度 OHLC 倾向序列。`all` 仅并列返回四派结果，绝不生成跨派加权结论。

## 审计接口

`GET /api/rules` 支持按流派、模块、时间层、来源、状态检索全部规则。

`GET /api/rules/:ruleId` 返回 RuleIR、If/Then 条件、效应、来源、版本、缺失或保留边界。

`GET /api/trace/:analysisId` 返回一次分析中每条已触发或被排除规则的输入事实、判定结果和输出。

## 地点接口

`GET /api/locations?q=` 返回 GeoNames 规范地点记录；地点记录必须包含经纬度、IANA 时区、坐标类型、来源版本和人口/行政层级，不能使用未标识来源的坐标。

## 产品页面与接口关系

| 页面 | 主要接口 | 深层入口 |
| --- | --- | --- |
| 总览 | chart compile + selected-school annual run | 年度抽屉、流年详情 |
| 时间线 | analysis run trajectory | 流年详情 |
| 流派 | rule profile catalog | 流派详情 |
| 规则库 | rules list/detail | 单条规则详情 |
| 排盘与计算 | chart compile certificate | 每一步计算证书 |
